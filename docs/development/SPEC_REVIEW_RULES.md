# 规格审查规则规范

## 目标

定义规格阶段之间的进入条件，保证功能设计完整后再进入下一阶段。

## 审查原则

每个阶段必须满足当前阶段目标，才能进入下一阶段。

禁止：

- 跳过规格阶段
- 在信息不足时进入实施
- 在规则未确定时开始开发

---

# 需求规格 → 产品规格

必须确认：

- 用户问题明确
- 目标用户明确
- 使用场景明确
- 成功标准明确
- 功能范围明确

输出：

需求规格通过。

---

# 产品规格 → 领域设计

必须确认：

- 用户流程明确
- 功能行为明确
- 权限范围明确
- 异常情况明确

输出：

产品行为可进入领域分析。

---

# 领域设计 → 架构规格

必须确认：

- 领域边界明确
- 核心概念明确
- 业务规则明确
- 与其他领域关系明确

输出：

领域设计冻结。

---

# 架构规格 → 数据规格

必须确认：

- 模块职责明确
- 数据流明确
- 依赖关系明确

输出：

可以设计数据对象。

---

# 数据规格 → 可执行规格

必须确认：

- 数据对象明确
- 数据生命周期明确
- 数据约束明确

输出：

设计规则完整。

---

# 可执行规格 → 实施规格

必须确认：

- 业务规则明确
- 边界条件明确
- 不允许变化内容明确

输出：

可以转换为实施方案。

---

# 实施规格 → 伪代码规格

必须确认：

- 功能流程完整
- 输入输出明确
- 状态变化明确
- 异常处理明确
- 权限规则明确

输出：

可以生成伪代码。

---

# 伪代码规格 → 开发实现

必须确认：

- 执行步骤明确
- 数据变化明确
- 行为结果明确
- 验收条件明确

输出：

进入实现阶段。

---

# 开发实现 → 验收完成

必须确认：

- 功能符合规格
- 行为符合预期
- 验收场景全部通过

输出：

功能完成。
