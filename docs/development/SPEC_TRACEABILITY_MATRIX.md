# 规格追踪矩阵规范

## 目的

规格追踪矩阵用于保证一个功能从提出到验收全过程保持一致。

核心目标：

需求、产品行为、领域规则、架构设计、数据设计、实施规格、伪代码规格、验收标准之间必须存在对应关系。

---

# 一、追踪链路

每个功能必须建立以下链路：

```
需求
 ↓
产品行为
 ↓
领域规则
 ↓
架构职责
 ↓
数据对象
 ↓
可执行规格
 ↓
实施流程
 ↓
伪代码步骤
 ↓
行为场景
 ↓
验收条件
```

---

# 二、追踪矩阵结构

|编号|规格对象|来源|目标|状态|
|-|-|-|-|-|
|1|需求|业务目标|产品规格|必须存在|
|2|产品行为|需求规格|领域设计|必须存在|
|3|领域规则|领域设计|可执行规格|必须存在|
|4|架构职责|架构规格|实施规格|必须存在|
|5|数据对象|数据规格|实施规格|必须存在|
|6|实施流程|实施规格|伪代码规格|必须存在|
|7|伪代码步骤|伪代码规格|行为规格|必须存在|
|8|行为场景|行为规格|验收规格|必须存在|
|9|验收条件|验收规格|完成判断|必须存在|

---

# 三、功能级追踪要求

每个功能必须回答：

## 为什么存在

对应：

- 需求规格

## 用户如何使用

对应：

- 产品规格

## 业务如何约束

对应：

- 领域设计
- 可执行规格

## 系统如何实现

对应：

- 架构规格
- 实施规格

## 数据如何变化

对应：

- 数据规格
- 实施规格

## 如何确认正确

对应：

- 行为规格
- 验收规格

---

# 四、缺失检查

进入下一阶段前必须检查：

- 是否存在无法追溯的实施步骤
- 是否存在没有来源的业务规则
- 是否存在没有验收条件的功能行为
- 是否存在没有数据定义的数据操作
- 是否存在没有需求来源的功能

---

# 五、功能完成标准

一个功能只有满足以下条件才认为规格完整：

```
需求可追溯
产品行为明确
领域规则明确
架构职责明确
数据对象明确
实施流程明确
伪代码完整
行为可验证
验收可判断
```
