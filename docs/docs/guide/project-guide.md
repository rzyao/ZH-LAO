# ZH-LAO 项目说明书

这是一份给人看的项目总览。第一次接触 ZH-LAO，先看这一页就够了；只有在需要参与产品设计、开发或验收时，才需要继续进入后面的详细文档和 Spec Kit。

## 一句话介绍

ZH-LAO 是一款面向中文用户和老挝语用户的双语学习与跨语言社交应用。

它不是把“背单词”和“交友”简单放在同一个 App 里，而是希望形成一条自然路径：用户先因为学习语言来到这里，再通过真实交流练习语言、认识朋友，并在安全机制下建立长期关系。

## 它解决什么问题

中文与老挝语之间的学习资料、发音内容和练习工具相对分散；真正需要交流时，用户又会遇到语言障碍、找不到合适对象和缺乏信任的问题。

ZH-LAO 希望把这些环节连起来：

- 老挝用户可以学习中文，也可以认识中文母语者并进行真实练习。
- 中文用户可以学习老挝语，也可以认识老挝朋友并建立关系。
- 内容团队可以在后台维护课程、词汇、例句、练习和标准音频。
- 运营团队可以处理账号、权限、审核、举报、平台配置等工作。

## 用户将怎样使用它

一个典型过程是：

```text
选择界面语言
  → 浏览学习内容
  → 用手机号或 Facebook 注册
  → 选择自己的学习方向
  → 学课程、词汇、发音和练习
  → 完善社交资料并通过必要审核
  → 发现合适的人、关注并建立联系
  → 使用文字、图片和语音等方式交流
```

学习和社交并不强制绑定。用户可以只使用学习功能；只有希望进入社交场景时，才需要补充资料并满足相应的准入与安全要求。

## 产品由哪些部分组成

### 移动端

这是普通用户使用的 App，首发重点平台是 Android。它承载登录、学习、词典、练习、社交发现、动态、聊天、钱包和设置等体验。

### 运营后台

这是内容编辑和运营人员使用的 Web 管理系统。它用于维护教学内容和音频、管理平台规则与版本、配置运营权限，以及处理后续的审核和安全工作。

### 后端服务

它负责账号与登录、教学内容、学习记录、社交关系、聊天、交易、奖励、安全审核和平台配置，是移动端与运营后台共享的业务核心。

### 数据库

项目使用 PostgreSQL 保存业务数据。不同业务有清晰的归属边界，但当前仍部署为一个整体系统，以降低早期开发和运维成本。

## 计划中的核心能力

### 语言学习

课程、字母与发音、词汇、句子、词典、练习、学习进度、复习，以及与学习相关的翻译能力。产品不以游戏化为主要方向。

### 跨语言社交

个人资料、发现与筛选、关注、互相关注、动态、评论和聊天。位置只用于距离计算和模糊展示，不向其他用户暴露精确坐标。

### 聊天与交流辅助

规划支持文字、表情、图片、语音消息、已读状态、撤回、翻译和语音转文字。具体能力会按开发和审核进度逐步开放。

### 商业化

学习侧可以采用基础免费、高级能力和广告等组合；社交侧主要围绕提高建联效率和虚拟礼物。资金与虚拟资产由独立的钱包和账本体系记录。

### 安全与运营

社交资料审核、举报、处罚、申诉和真人认证会形成独立的安全链路。运营人员通过角色和权限工作，重要后台操作需要留下审计记录。

## 项目现在做到哪里了

截至 2026 年 9 月 2 日，项目仍处于开发阶段，**还不是可正式发布的完整产品**。

已经完成并通过项目验收的基础部分包括：

- PostgreSQL 数据库基线与迁移体系；
- 后端应用基础；
- 运营后台基础框架；
- 移动端基础框架；
- 用户身份、登录与会话相关后端能力；
- 平台配置能力；
- 运营人员、角色、权限和操作审计相关后端能力。

当前工作的重点是教学内容，包括老挝语字母及其相关内容管理能力。仓库中可能已经能看到正在开发的页面和接口，但在正式验收前，它们仍应视为开发中功能。

以下主要用户旅程尚未整体打通：

- 完整的课程学习和学习进度；
- 社交资料、发现、关注和匹配；
- 完整聊天体验；
- 钱包、支付、礼物和奖励；
- 举报、审核与申诉；
- 面向真实用户的全系统联调、发布准备和上线。

因此，当前版本更适合产品设计、开发和内部演示，不适合当作已经完成的成品介绍给最终用户。

## 如何在本机查看

项目为 Windows 准备了几个双击启动脚本。第一次运行前需要安装 Node.js 和 pnpm；后端业务功能还需要可用的 PostgreSQL 数据库和正确的本地环境配置。

- 双击 `双击启动文档.bat`：打开这套项目文档，地址为 `http://127.0.0.1:15172`。
- 双击 `双击启动Admin.bat`：打开运营后台，地址为 `http://127.0.0.1:15173`。
- 双击 `双击启动移动端.bat`：默认在浏览器中预览移动端，也可选择连接 Android 模拟器。
- 双击 `双击执行数据库迁移.bat`：初始化或升级本地数据库。
- 双击 `双击启动后端.bat`：启动后端服务，默认地址为 `http://127.0.0.1:18080`。

这些程序是独立启动的。要体验需要真实数据的完整流程，通常应先准备数据库，再启动后端，最后启动 Admin 或移动端。仅查看界面和文档时，不一定需要全部启动。

## 目录里都是什么

- `apps/mobile/`：普通用户使用的移动端。
- `apps/admin/`：内容和运营人员使用的后台。
- `apps/backend/`：业务接口与后台任务。
- `database/`：数据库结构、迁移和校验工具。
- `docs/`：产品、开发和架构文档；本说明书也在这里。
- `specs/`：Spec Kit 生成的功能规格、计划和任务，主要供 AI 与实现流程使用。
- `.specify/`：Spec Kit 的模板、规则和自动化配置，不是日常阅读入口。
- `scripts/`：项目检查和文档维护工具。

## 项目原则

- 先把学习体验做好，让用户有持续使用的理由，再逐步开放社交和商业能力。
- 学习用户不自动获得社交资格，社交能力有独立的资料和安全门槛。
- 不向用户暴露精确位置，不把敏感凭据保存在不安全的位置。
- 金钱和虚拟资产必须有可追溯记录；重要运营操作必须可审计。
- 早期采用一个结构清晰的整体系统，控制单人开发和运维成本，不为了“看起来先进”过早拆成大量服务。
- 功能可以提前建设，但是否对用户开放由平台配置控制。
