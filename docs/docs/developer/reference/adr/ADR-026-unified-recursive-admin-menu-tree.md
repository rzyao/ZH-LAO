# ADR-026：后台菜单采用统一递归目录树

> 后续交互修订：可导航目录的整行点击行为由 [ADR-027](ADR-027-navigable-directory-row-toggle.md) 规定；原“跳转与展开完全分离”已被取代。

**状态：** `已接受`

**日期：** `2026-09-04`

**批准：** 用户明确要求移除分组功能并允许自由嵌套，登记 D-165 / Product Forge CR-004。

**修订：** [ADR-022](ADR-022-platform-menu-routing-config.md)、[ADR-024](ADR-024-menu-tree-reparenting.md)、设计台账 D-155 / D-159 / D-163

## 背景

历史导航把节点区分为分组、一级菜单和子菜单，并在应用层限制三层。该区别来自旧侧边栏的
展示方式，不是业务事实；它导致内容目录需要额外桥接节点，也让中文内容和老挝语内容的
字号、展开行为及管理方式与普通菜单不一致。

## 决策

1. `platform.menus` 中的所有记录统一称为菜单节点，不再存在专门的分组类型。
2. `parent_id IS NULL` 只表示根节点；任意未移除节点均可作为父节点并自由递归嵌套。
3. `route_key` 始终可选。无路由节点是目录；有路由节点也可以继续拥有子节点。
4. 移除业务层三层上限，保留自环、后代环、父节点不存在或已移除、并发冲突等完整性校验。
5. 侧边栏递归渲染同一种节点样式。所有含子节点的目录默认收起；目录和页面名称统一使用
   正常导航字号。带路由且含子节点时，跳转与展开使用两个独立操作。
6. 菜单管理页允许在任意层级新建子节点、同级排序及拖拽换父级。
7. 通过前向迁移 `1330_platform_menu_recursive_directories.sql` 停用旧展示分组桥接节点并
   归一化初始树；不修改冻结迁移，也不改变表结构、权限 OR、路由白名单或审计模型。

## 后果

- 导航结构只由父子关系表达，可以按运营需要持续增减目录层级。
- 中文内容和老挝语内容是普通目录，不再使用特殊标题或分组样式。
- API 的 `groups` 响应字段暂保留为根节点集合的传输字段名，不再代表领域中的“分组”。
- 极深目录虽不受业务上限限制，管理端仍必须防止环并递归执行权限过滤、面包屑和渲染。
