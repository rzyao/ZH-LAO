# ADR-024：后台菜单树支持拖拽换父级

> 后续修订：菜单分组语义与最大三层限制已由 [ADR-026](ADR-026-unified-recursive-admin-menu-tree.md) 取代；本记录的原子移动、环检测与并发校验继续有效。

**状态：** `已接受`

**日期：** `2026-09-04`

**批准：** 用户确认 CR-001，2026-09-04

**修订：** [ADR-022](ADR-022-platform-menu-routing-config.md)、设计台账 D-155

## 决策

Admin 菜单仍使用 `platform.menus.parent_id` 的邻接表与最大三层深度，但不再以
`parent_id IS NULL` 推导菜单类型。任一未移除菜单项都可位于顶层或其他菜单项下，且可
同时拥有白名单 `route_key` 与子项；没有 `route_key` 的节点只是不可点击的容器。

菜单管理页提供拖拽排序和拖拽换父级。移动操作必须原子地更新父级和两个受影响层级的
连续 `sort_order`，拒绝自我挂载、挂载至自身后代、移除节点作为父级，以及使被移动子树
超过三层的请求。移动时同时校验节点及源/目标层级快照；不匹配返回既有并发冲突语义。

新增 `POST /api/v1/admin/platform/menus/:id/move` 管理端点，复用 `platform.menus.write`
授权与不可变操作审计。它不改变数据库表、权限模型、路由白名单或菜单可见性的 OR 语义。

## 后果

- 顶层分组可以拖入其他菜单；带路由的普通菜单也可以拖回顶层。
- 前端导航规范化不得假设“顶层必为分组”或“父菜单不能跳转”。
- 原有 `PUT .../order` 继续用于纯同层重排；跨层拖拽使用新移动端点。
