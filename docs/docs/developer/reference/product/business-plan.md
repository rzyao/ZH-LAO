# 首发后 12 个月业务规划

本页是创始人内部执行使用的经营规划基线，负责把已经确认的产品方向转化为阶段目标、验证动作、指标和复盘节奏。产品定位以[产品定位与范围](product-overview.md)为事实源，商业机制以[业务与商业模型](business-model.md)为事实源，能力开放以[功能开放与产品规则](feature-rollout.md)为事实源；本页不复制领域、价格、数据库或实现契约。

## 1. 已确认的经营基线

- 产品是面向中文与老挝语用户的双边平台：学习负责获客、留存和差异化，社交负责关系形成，社交效率和虚拟礼物是主要商业化方向。
- 首发平台为 Android，中老用户同时服务，不以中国大陆应用商店为主要发行渠道。
- 第一阶段按约 10,000 注册用户设计；核心指标为注册量，其次观察 DAU/MAU。
- 项目由单人主导开发，资金和人力有限；运营能力按未来多人协作设计，但经营节奏必须服从真实资源。
- 学习面向全年龄用户开放；社交资料、发现、Match 与聊天需要独立准入和安全治理。
- 首期不以大型分布式系统或机器学习推荐为目标，也不以未经验证的功能数量替代真实用户价值。

## 2. 双边用户与价值路径

### 老挝语界面用户

主要价值路径为：学习中文 → 获得可持续学习价值 → 真人练习与公开互动 → 认识中文用户 → 建立关系。用户画像、主要城市、年龄分布、获客渠道和付费意愿均为 `designing`，必须通过首批访谈与行为数据验证。

### 中文界面用户

主要价值路径为：学习老挝语或了解老挝用户 → 发现与关注 → 互相关注形成 Match → 免费聊天 → 按需购买社交效率或虚拟礼物。具体细分人群、核心动机和支付能力为 `designing`。

### 双边供给约束

双边增长不能只看总注册量。每次经营复盘必须同时观察两侧新增、有效资料、可发现用户、互动发起、互关和 Match，避免一侧增长掩盖另一侧供给不足。正式供需平衡阈值在获得真实数据前保持 `designing`。

## 3. 十二个月阶段计划

### 首发准备期

目标是证明产品能够安全、稳定地完成最小价值闭环，而不是提前证明规模化增长。

- 完成 Android 首发所需学习、账号、社交准入、发现、关系、聊天和运营治理的真实端到端验收。
- 建立事件口径，至少能够区分用户来源、界面语言、学习激活、社交准入、Follow、Match、聊天与付费漏斗。
- 完成首批目标用户访谈、可用性测试、内容质量抽检和社交安全演练。
- 冻结首发渠道清单、支付接入范围、客服与事件响应流程；没有证据的渠道和支付选择不得写成既定结论。

进入下一阶段的条件：核心旅程通过真实设备验收；关键指标可被可信采集；安全和运营处置可执行；不存在阻塞上线的高风险问题。具体数值门槛为 `designing`，由首发准备数据确定。

### 首发后 0–3 个月：验证激活与供给

- 验证两侧用户是否理解产品定位，以及学习入口能否带来有效激活。
- 验证从学习或内容浏览到社交资料申请、审核通过、发现和首次互动的主要流失点。
- 以定性访谈、漏斗数据和留存队列识别最需要修复的前三个问题，避免以新增功能替代问题修复。
- 商业化只做可观测的意愿验证；未完成支付、定价与合规验证前，不承诺收入目标。

进入下一阶段的条件：能够解释主要获客来源、激活行为、早期留存和双边供给问题；核心漏斗数据稳定；形成可重复的小规模运营流程。目标值在首月真实基线形成后决定。

### 首发后 3–6 个月：验证留存与关系价值

- 验证学习内容、社区互动、发现、Match 和聊天中哪些行为与留存真正相关。
- 按地区、界面语言、获客来源和社交资格分群复盘，不使用单一总体 DAU/MAU 掩盖结构问题。
- 仅在安全、供给和留存基础稳定后验证社交效率权益；Match 后正常聊天继续永久免费。
- 验证运营人员是否能独立完成内容、审核、配置、举报和必要的商业操作。

进入下一阶段的条件：至少有一条可解释的留存路径和一条可重复的关系形成路径；商业化实验不会破坏免费核心关系；运营工作量可被记录和评估。数值门槛保持 `designing`，在 0–3 个月复盘时冻结。

### 首发后 6–12 个月：验证可持续经营

- 在已验证渠道中测试可重复获客，停止无法证明有效性的渠道投入。
- 评估社交会员、单项 Entitlement 或虚拟礼物的真实需求、支付成功率、退款和风控成本。
- 建立收入、支付成本、内容成本、审核成本、客服成本和基础设施成本的月度经营视图。
- 依据真实使用和运营负担决定下一年度重点，不以提前扩展国家、平台或复杂推荐系统作为默认方向。

阶段完成条件：形成下一年度可选择的经营方案，并能用真实数据解释用户价值、增长来源、留存、付费和主要成本。盈利或收入目标在定价与单位经济验证前保持 `deferred`。

## 4. 经营漏斗与 KPI 字典

| 层级 | 指标 | 当前口径 | 数据来源 | 目标状态 |
| --- | --- | --- | --- | --- |
| 获取 | 注册用户数 | 成功创建正式账号的去重用户 | Identity 注册事实 | 首期约 10,000；阶段节奏 `designing` |
| 活跃 | DAU / MAU | 当日/月内发生有效产品行为的去重用户 | 事件分析层，事件集合待冻结 | 观察指标；目标值 `designing` |
| 学习激活 | 首次有效学习 | 完成首个可验证学习行为 | Learning 事实与事件 | 定义及目标 `designing` |
| 社交供给 | 可发现用户 | 满足准入、审核和可发现条件的用户 | Social / Trust 事实 | 双侧目标 `designing` |
| 关系形成 | Follow → Mutual Follow → Match | 按冻结关系语义逐层转化 | Social 事实与事件 | 分侧、分来源观察；目标 `designing` |
| 沟通价值 | Match 后有效聊天 | Match 后产生符合口径的真实互动 | Chat 事实与事件 | 有效口径和目标 `designing` |
| 留存 | D1 / D7 / D30 与队列留存 | 按注册或首次激活队列观察 | 分析层 | 目标值 `designing` |
| 商业意愿 | 权益或礼物转化 | 从曝光、意向到支付成功的漏斗 | Commerce 事实 | 产品、价格和目标 `deferred` |
| 安全 | 举报与处置质量 | 举报、响应、处置、申诉与误判 | Trust / Operations 事实 | SLA 与目标 `designing` |

事件定义、去重规则、时区、机器人和内部账号排除规则必须在正式仪表盘上线前冻结。没有可信数据源时不得展示模拟 KPI。

## 5. 三条商业验证路径

### 学习价值

验证问题：免费学习内容能否持续带来激活和留存；高级学习能力、AI 翻译、TTS 或广告是否存在真实需求。具体能力组合、价格和广告策略均为 `designing`，验证前不得建立收入预测。

### 社交效率

验证问题：中国用户是否愿意为更多 Follow、推荐机会、高级筛选、信息查看或曝光等具体 Entitlement 付费。必须逐项验证价值，不使用笼统的 `user.vip`。Match 后正常聊天永久免费是当前基线。

### 虚拟礼物

验证问题：礼物是否能表达关系价值且不引入不可接受的支付、退款、欺诈和审核成本。接收者收益、提现、结算和 Creator Economy 为 `deferred`，不得进入首期财务假设。

## 6. 市场、渠道与竞争验证

以下内容尚无足够仓库证据，统一按假设管理：

| 主题 | 状态 | 验证动作 | 所需证据 | 决策时点 |
| --- | --- | --- | --- | --- |
| 优先用户细分 | `designing` | 两侧分别开展结构化访谈和首发招募 | 动机、替代方案、使用场景和拒绝原因 | 首发准备期 |
| 首发地区与城市 | `designing` | 对比用户供给、渠道可达性和运营成本 | 有效招募、激活和社交供给数据 | 首发前 |
| 获客渠道 | `designing` | 小批量、可归因地测试候选渠道 | 每渠道有效注册、激活、留存与成本 | 0–3 个月 |
| 竞品与替代方案 | `designing` | 访谈用户当前使用的学习、社交和翻译产品 | 真实替代行为与未满足需求 | 首发准备期至首月 |
| 支付渠道 | `deferred` | 核对中老两侧可用性、合规、费率和退款能力 | Provider 条款、成功率、结算和风险 | 商业实验前 |

## 7. 定价、预算与单位经济

- 具体定价、套餐、免费额度、广告组合、收入预测和预算均为 `designing` 或 `deferred`。
- 商业实验开始前必须记录：价格、适用人群、权益、实验周期、成功标准、停止条件和退款规则。
- 月度成本至少区分基础设施、内容生产、音频生产、审核、客服、支付费率、退款与渠道投入。
- 在获得真实转化、退款、支付成本和服务成本前，不计算或承诺 LTV、CAC 回收期或利润率目标。
- 经营复盘可以展示“未知”或“数据不足”，不得用示例数字替代事实。

## 8. 经营节奏与责任

- 每周：检查产品稳定性、关键漏斗异常、安全事件和当前验证任务。
- 每月：按用户侧、地区、来源和资格状态复盘增长、激活、留存、关系、商业意愿与成本。
- 每阶段结束：冻结下一阶段目标、指标口径和停止事项；未达到进入条件时先修复问题，不自动扩张范围。
- 当前由创始人承担产品与经营决策；未来运营人员加入后，再在不改变领域事实所有权的前提下分配执行责任。

## 9. 主要风险

| 风险 | 早期信号 | 当前应对 |
| --- | --- | --- |
| 双边供给失衡 | 一侧可发现用户、Follow 或 Match 明显不足 | 分侧观察并限制单侧无效扩量；调整招募与开放范围 |
| 学习价值不足 | 注册后没有有效学习或短期快速流失 | 优先修复内容、引导和学习闭环，不先增加商业限制 |
| 社交安全与信任不足 | 审核积压、举报上升、误判或骚扰 | 保持独立准入、人工审核、举报与处置证据链 |
| 过早商业化 | 付费限制降低关系形成或引起投诉 | 保持 Match 后正常聊天免费；商业实验小范围、可回退 |
| 单人资源过载 | 开发、内容、审核和客服同时阻塞 | 按阶段 Gate 收缩范围，记录真实运营工作量 |
| 数据不可用 | 指标无法追溯或口径频繁变化 | 先冻结事件和口径，再设目标或扩大投入 |

## 10. 当前验证队列

1. 冻结首发核心旅程与分析事件口径。
2. 完成两侧首批用户访谈和替代方案记录。
3. 建立按界面语言与用户侧拆分的获取、激活、社交供给和关系漏斗。
4. 用首月数据冻结 0–3 个月的数值目标和阶段退出条件。
5. 在商业实验前单独裁决支付、定价、Entitlement 和合规范围。

本页每次更新只记录当前经营基线。已被新证据否定的假设应直接更新，并在设计台账或变更记录中保留决策来源；不得创建 `business-plan-v2.md` 等平行版本。
