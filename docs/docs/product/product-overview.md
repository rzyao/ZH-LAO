# 产品定位与范围

## 产品本质

ZH-LAO 不是简单地把学习和交友拼在一起，而是一个双边平台：

> 以中老双语学习获取用户，以跨语言社交建立关系，以中国用户购买社交效率和虚拟礼物作为主要商业化方向。

| 用户侧 | 首要认知 | 价值路径 |
| --- | --- | --- |
| 老挝用户 | 学中文的应用，也能认识中国朋友 | 学中文 → 真人练习 → 认识中国朋友 → 社交 → 贡献获得权益 |
| 中文用户 | 认识老挝人的应用，也能学习老挝语 | 学老挝语 → 认识老挝人 → 建立关系 → 免费聊天 → 付费提高社交效率 |

两侧的首页、营销表达和功能重点可以不同，但账户、学习、社交与商业底层共用同一平台。

## 阶段目标与约束

- 首发平台为 Android。
- 中老用户同时上线，但不以中国大陆应用商店为主要发行渠道。
- 第一阶段规模按约 10,000 注册用户设计；核心指标为注册量，其次观察 DAU/MAU。
- 资金和人力有限，由单人主导开发，未来会招运营人员。
- 主要能力提前建设，再由配置逐步开放；架构追求低成本、低运维与可扩展，而非大型分布式系统。

## 四大产品支柱

### Learning

综合学习体系，包括课程、单词/词汇、词典、发音、TTS、练习、听说读写和翻译。不做游戏化。学习承担获客、留存和产品差异化。

### Social

提供丰富交友资料、发现、筛选、位置距离、Follow、互相关注形成 Match，以及 Match 后聊天。重点关系供给是中国男性与老挝女性，但底层数据模型不排除其他用户。

### Monetization

学习可采用基础免费、高级功能、AI/TTS、广告等组合；社交主要出售建联效率。虚拟礼物是独立收入线。

### Operations

运营后台从第一天按多人协作设计，覆盖用户、审核、举报、课程、商业、奖励、配置、权限和数据看板，不是简单 Admin CRUD。

> 域边界说明（设计运营域会话）：后台能执行「封禁/退款/补发」等，但 **Operations 域本身只拥有后台运营主体、RBAC 授权与后台操作审计（5 张表）**；封禁/举报等审核事实归 Trust、退款归 Commerce、奖励补发归 Rewards，Operations 只记录「谁在何时执行了什么后台操作」。完整边界见 [Operations 域](../domains/operations/index.md)。

## 用户与资格生命周期

```text
打开 App → 选择中文/老挝语界面 → 游客浏览学习内容
→ 手机号/Facebook 注册 → 固定学习方向 → Learning User
→ 申请 Social Profile → 完善资料/照片 → 真人认证 → 人工审核
→ Social Eligible → 发现/关注/Match/聊天
```

学习对全年龄用户开放；社交拥有独立准入和安全体系。用户成为 Learning User 不代表自动获得社交资格。

## 首期功能边界

| 范围 | 包含 | 不包含 |
| --- | --- | --- |
| 学习 | 中文/老挝语知识、课程、练习、词典、发音、进度、AI 翻译 | 游戏化 |
| Community | 朋友圈式文字、图片、点赞、评论、关注后 Feed、举报 | 视频动态 |
| Chat | 文字、Emoji、图片、语音消息、撤回、已读、翻译、语音转文字 | 文件、视频通话、语音通话 |
| 位置 | 服务端用于距离计算，前台模糊显示 | 对用户暴露精确坐标 |
| 审核 | 前期人工，后期自动化辅助与人工复核 | 首期完全自动化 |

上表 Chat 行列出「语音消息、翻译、语音转文字」为产品首期范围；但 Chat Domain 数据库设计定稿时首期消息类型只到 `TEXT` 与 `IMAGE`，语音与翻译尚未进入数据库设计。该差异由主架构会话裁决，已记入[未决事项](../governance/open-questions.md)，在裁决前产品范围与数据库范围并存记录。
