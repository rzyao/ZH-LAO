# 产品规格：管理端通用数据表增强

> 状态：APPROVED｜版本：1.3｜日期：2026-09-05｜规模：中等
>
> Feature：`admin-data-table-enhancement`｜相关：[研究](../research/README.md)｜[旅程](./journeys/journeys.yml)｜[线框](./wireframes/)

## 1. 概览

内容管理员需要在大量老挝字母记录中定位、审核与处置一组记录。首期将 `/content/lo/letters` 迁移到可复用的管理端 DataTable 能力：服务端搜索/筛选/排序/分页、固定操作列、列显示设置、跨页选择和异步批量命令。

研究显示现有 DataTable 是可复用的客户端基础，但当前实现尚未提供本功能所需的服务端查询和批量命令。相关目标契约现已由 D-167、ADR-028 与 Content API 接受；本规格不宣称现有代码已经实现这些契约。

## 2. 用户

**主要用户：内容管理员。** 在日常审核工作中处理老挝字母的工作修订，期望明确知道查询范围、选择范围、操作影响与任务结果。

## 3. 用户故事

### Must Have

- **US-001**：作为内容管理员，我要搜索、筛选、排序和分页浏览字母记录，以便定位审核队列。
- **US-002**：作为内容管理员，我要设置非关键显示列，同时始终看到操作列，以便在信息密度与可操作性间平衡。
- **US-003**：作为内容管理员，我要从本页选择升级到当前筛选结果全部，以便处理跨页的同类审核工作。
- **US-004**：作为内容管理员，我要确认并提交受权限与状态机约束的批量动作，以便安全地处理记录。
- **US-005**：作为内容管理员，我要看到异步批量任务逐项的成功、失败和跳过原因，以便采取后续行动。

### Must Have 验收标准

- **AC-US-001**：给定有效的字母列表查询，当管理员改变关键词、筛选、排序、页码或页大小时，服务端返回稳定且可复现的一页结果与总数；改变关键词、筛选或页大小后回到第一页，刷新页面保持查询状态。
- **AC-US-002**：给定字母列表，当管理员隐藏或恢复可配置列时，表格立即反映设置；操作列始终固定且不可隐藏，批量选择启用时选择列亦不可隐藏。
- **AC-US-003**：给定多页查询结果，当管理员选择本页全部后，可显式升级为当前筛选结果全部并看到范围及总数；任何会改变目标集合的查询变化均清空旧选择。
- **AC-US-004**：给定至少一条选择，提交审核、通过、驳回、正式发布或软删除都必须显示动作、范围和数量并二次确认；驳回和软删除无有效原因时不能提交；服务端按动作权限及状态机逐项校验。
- **AC-US-005**：给定已提交任务，管理员可看到任务状态、汇总计数和分页的逐项结果；部分成功不回滚成功项，失败项可重试，成功/跳过项不重复执行，任务不可取消且历史长期可查。

### Should Have

- 清除全部筛选、恢复默认列、请求失败重试，以及在数据变化后提示重新加载/选择。

### 首期不包含

- 上线、下线、导出、保存或共享筛选视图；不新增通用“任意批量写入”组件。

## 4. 功能需求

| ID | 要求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| FR-001 | 字母列表支持服务端关键词搜索、白名单筛选、白名单排序与稳定分页。 | Must | 搜索字符/名称/罗马化；筛选字母类型、字母类别、内容状态、工作修订状态；排序号/字符/名称/罗马化/更新时间可排序；默认 50 条、最大 500 条。 |
| FR-002 | 查询、筛选、排序和分页状态存入 TanStack Router Search Params。 | Must | 改变查询或页大小时回到有效第一页。 |
| FR-003 | 操作列固定且不可隐藏；选择列也不得在启用批量选择时隐藏。 | Must | 其他显示列可由用户切换。 |
| FR-004 | 表头选择默认只选当前页，并清楚显示选中数量。 | Must | 三态复选框和键盘操作符合可访问性要求。 |
| FR-005 | 当前页全选后，界面可显式升级为当前筛选结果全部。 | Must | 显示查询范围与总数；筛选/排序变化后旧选择失效。 |
| FR-006 | 可用批量动作仅由 Content 返回或页面的领域声明提供。 | Must | 通用表格不决定动作资格。 |
| FR-007 | 所有批量动作均先显示动作名、范围与数量，并经二次确认。 | Must | 驳回和软删除要求非空原因。 |
| FR-008 | 批量动作异步执行，无数量上限，并逐条校验。 | Must | Content 拥有任务；提交时冻结匹配记录 ID，后台按小批次处理；返回任务标识及逐项成功/失败/跳过结果。失败项可重试，任务提交后不可取消，任务及逐项结果长期保留。 |
| FR-009 | 批量任务完成后刷新当前查询；页面保留有效条件与页码。 | Must | 空页时跳至最近有效页。 |
| FR-010 | 加载、无记录、无筛选结果、错误、任务进行中和部分完成均有明确状态。 | Must | 不以空态代替加载或错误。 |
| FR-011 | 每个成功的后台业务动作按 Operations 审计边界记录。 | Must | 具体 action key/target/result 由 Owner Domain 契约定义。 |
| FR-012 | 所有新增 API 使用 ADR-023 的统一响应信封。 | Must | 不引入第三种响应结构。 |

## 5. 待批准的 Content / Operations 契约

| 契约提议 | 当前状态 |
| --- | --- |
| `API-LettersQuery`：受控搜索、筛选、排序、分页及总数返回 | 已由 Content API 契约接受 |
| `API-LettersSelectionPreview`：当前查询全部的稳定范围/计数 | 已由 Content API 契约的规范化查询、目标 UUID 集合 hash 和 expected count 接受 |
| `API-LettersBatchStart`：提交审核、通过、驳回、正式发布、软删除的异步命令 | 已由 D-167 / ADR-028 与 Content API 契约接受 |
| `API-LettersBatchTask`：进度、失败项重试与逐项结果 | 已由 D-167 / ADR-028 与 Content API 契约接受；Operations 仅负责授权与审计 |
| 状态守卫、权限、软删除条件、幂等/并发、审计 action key | 已由 D-167 / ADR-028 与 Content API 契约接受 |

已批准的产品基线是：批量任务归 Content 所有，Operations 只负责授权与审计；提交任务时冻结当前查询匹配的记录 ID，后台工作进程按小批次处理；失败项可以重试，任务提交后不可取消；任务及其逐项结果长期保留。批量动作逐条执行：不符合状态或权限的对象记为跳过/失败并给出安全原因，其他对象继续处理。提交审核、通过、驳回、正式发布必须遵守现有 Content Revision 状态机；管理端“删除”按权威契约执行 `archive` 软删除。查询白名单、两表持久化、任务 API、权限、幂等、陈旧选择拒绝、任务状态与审计边界均已由 D-167 / ADR-028 及 Content API 契约接受。

## 6. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 可访问性 | 满足 WCAG 2.1 AA；复选框支持混合状态，菜单/对话框有键盘焦点与明确名称，状态更新使用可读提示。 |
| 安全 | 前端权限仅作引导；服务端逐条授权和状态校验为唯一安全边界。 |
| 可用性 | 网络错误可重试并保留查询；任务中防止重复提交。 |
| 一致性 | 保持 React、TanStack Table/Query/Router、Base UI 和现有设计令牌；不新增表格库或全局状态库。 |

## 7. 成功标准

- 内容管理员可在一个列表完成搜索、筛选、排序、分页、列设置、跨页选择、确认与提交批量审核。
- 批量任务结果清楚区分成功、失败和跳过，且不丢失有效查询条件。
- 所有测试旅程覆盖 P0/P1 边界；没有未经定义的批量 API 或权限旁路。

## 8. 风险与开放问题

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 字母列表单页上限较高 | 中 | 默认 50、最大 500；查询使用服务端分页、白名单字段和稳定排序，技术计划必须验证索引与响应时间。 |
| 无上限异步任务的资源保护 | 中 | 无产品数量上限；服务端以配置化小批次、并发与队列限流保护，限流可重试。 |
| 跨页选择随结果变化而过期 | 中 | 提交时校验规范化 query hash 与数量；变化则拒绝并要求重新选择。 |
| ADR-023 尚有存量实现漂移 | 中 | 新 API 直接采用统一信封，触及旧接口时单独决定迁移范围。 |
