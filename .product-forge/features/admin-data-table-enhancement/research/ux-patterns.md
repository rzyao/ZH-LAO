# UX/UI Patterns: 后台数据表能力补全

> 生成日期：2026-09-04  
> 研究范围：供内容管理员在后台列表中搜索、筛选、跨页浏览、选择多条记录并进行审核等批量操作。本文件是 UX 研究证据与建议，不定义业务状态机、权限或最终产品决策。

## 核心用户流程

### 主路径（审核待处理内容）

1. 内容管理员进入某一内容列表，先看到当前结果总数、可筛选字段、搜索入口和默认排序；其心智模型是“先缩小工作队列，再处理同类记录”。
2. 管理员以全局搜索定位已知标题、标识或作者，再以状态、语言、内容类型、日期等可组合的分面筛选进一步缩小范围。搜索与筛选生效后，应清楚显示结果数和已应用条件，且把页码重置为第一页。
3. 管理员在表格中逐行勾选；表头复选框默认仅代表**当前页**。选中后，原工具栏切换为上下文批量操作栏，显式显示“已选择 N 条”，仅呈现当前选择可执行的操作。
4. 当当前页已全选且查询还有更多匹配项时，界面可提供第二步、文字明确的选择：例如“已选择本页 50 条。选择全部 1,236 条匹配结果”。不得把“全选”静默扩大为跨页或跨筛选结果集的操作。
5. 管理员执行审核动作；对于不可逆、会改变发布可见性或可能部分失败的动作，先展示操作名称、对象数、作用范围与可选备注/确认。提交后保留可追踪的完成摘要（成功、失败、跳过数量及下一步），并按领域状态机与权限契约执行。
6. 操作完成后刷新受影响结果，保留仍有效的查询、筛选、排序和页码；若当前页已空，移动到最近的有效页，并以状态消息告知结果。

### 替代路径

- **只查找，不批量处理：** 在搜索框输入后显示“正在搜索/共 N 条结果”；空查询与无匹配结果采用不同文案，避免误以为数据尚未加载。
- **按一项属性聚焦队列：** 使用可多选的分面筛选；已应用条件显示为可单独移除的标签，并提供“清除全部”。筛选菜单中应显示各选项的可用性与数量（若后端可可靠提供）。
- **跨页检查：** 使用分页器浏览，分页器持续显示当前范围、总数（若可知）和每页数量。改变每页大小或查询范围时，应重新解释选择范围，而不能含糊保留“全选”。
- **列太多：** 通过“列”/“显示设置”菜单让管理员隐藏非关键列；固定选择列、行主标识和行操作列，列配置是本地展示偏好而不是数据权限机制。
- **部分记录不符合批量动作条件：** 将不合资格的原因在选择前或确认前说清；不要让按钮看似成功而在后台静默跳过。确认结果需分别报告成功、失败和跳过。
- **网络失败或数据变化：** 保留用户输入和筛选，显示可重试的行内错误；对过期选择、并发修改或权限变化，提示重新加载/重新选择，而非将旧选择继续提交。

## 状态清单

| 状态 | 触发条件 | 建议模式 |
|---|---|---|
| 初始空列表 | 当前资源尚无任何记录 | 说明该列表用途；在权限允许时提供首个创建/导入入口；不要显示筛选无结果的文案。 |
| 筛选/搜索无结果 | 资源有记录，但当前查询条件没有匹配 | 显示查询或条件摘要、`清除筛选`，保留筛选控件；不要提供“创建首条”作为唯一动作。 |
| 首次加载 | 进入列表或切换主查询 | 用与最终列数/行高相符的骨架屏，保留表头和工具栏的空间，避免布局跳动；不要以空态替代加载态。 |
| 局部加载 | 翻页、改筛选、刷新 | 让既有结果保持可见但标注正在更新，或以表体骨架替换；防止重复提交并避免全页闪烁。 |
| 加载错误 | 请求列表、分页或筛选失败 | 在表格区域显示简明错误、保留查询条件和明确的“重试”；同时提供请求标识给支持人员。 |
| 已选择 | 一条或多条记录勾选 | 上下文批量栏显示已选数、取消选择与适用动作；表头复选框正确呈现未选/混合/全选。 |
| 处理确认 | 执行有风险的批量审核/发布/拒绝 | 对话框/确认面板说明动作、范围、数量、影响和不可逆性；默认焦点置于标题或说明，按钮文字使用具体动词。 |
| 批量进行中 | 服务端接受任务或同步处理 | 禁用重复提交，展示进度或“正在处理 N 条”；允许安全取消仅在后端支持时提供。 |
| 批量完成/部分完成 | 处理返回结果 | 状态消息播报摘要；可查看失败/跳过记录和原因，筛选条件不丢失。 |
| 列配置 | 管理员打开列显示菜单 | 复选项使用可访问的菜单/弹出层；至少保留行主标识、选择与必要操作列，并提供恢复默认。 |

## UI 模式库

### 1. 表格工具栏：全局工具与上下文批量栏分离

Carbon 的数据表把搜索、筛选、显示设置、导出等放在表格工具栏；有选中行时显示批量操作栏。这一模式能把“改变结果集”的全局行为，与“作用于已选对象”的行为区分开来。建议将高频搜索保持可见，复杂筛选收进可见标签/面板；批量栏出现时提供已选数与清除选择。来源：[Carbon Data Table](https://carbondesignsystem.com/components/data-table/usage/)。

### 2. 双阶段全选：本页 → 当前查询全部

先以原生复选框选中当前页，再以明确、可撤销的文字链接/按钮升级范围。表头应是三态：全未选、部分选中、当前页全选；三态复选框的 `aria-checked="mixed"` 与 Space 键行为有明确的 WAI-ARIA 规范。该模式特别适合分页列表，能避免内容管理员误以为只审核当前页或误以为已审核所有页。来源：[WAI-ARIA Checkbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/)。

### 3. 分面筛选 + 已应用条件摘要

用与业务字段对应的分面（如审核状态、内容类型、语言、日期）作为可组合条件；所有已应用条件在工具栏下方以可移除标签呈现，并给出“清除全部”。避免在同一工具栏堆放所有筛选控件，以免造成视觉负担；复杂条件可在筛选面板内编辑。Carbon 明确将复杂筛选和表格设置置于工具栏，作为该模式的参考。来源：[Carbon Data Table](https://carbondesignsystem.com/components/data-table/usage/)。

### 4. 受控列显示与主键列保护

“列”按钮应打开带复选框的列清单，说明当前已显示数量，并支持恢复默认。建议固定首列（选择）与内容主标识，限制将所有识别信息隐藏；小屏或高缩放时优先隐藏低价值列，提供横向滚动而非破坏表头—数据单元格关系。USWDS 同时建议减少不必要列，并在有意义时才提供排序。来源：[USWDS Table](https://designsystem.digital.gov/components/table/)。

### 5. 可理解的分页

分页固定在表格底部，含上一页/下一页、当前页、当前显示范围、每页数量和总数（总数已知时）。以 `<nav>`、描述性 `aria-label`、列表结构和 `aria-current="page"` 提供语义；页数很大时显示相邻页面、首末页与省略号。来源：[USWDS Pagination](https://designsystem.digital.gov/components/pagination/)。

## 微交互与动效

- 选中第一行时，以短暂淡入/高度过渡显示批量栏；不得仅依赖颜色表达选中状态，同时更新可见计数。
- 筛选标签删除、清除全部、列显示切换应即时反馈；数据重新获取前标示“正在更新”，防止用户把旧表格误认成新结果。
- 搜索应采用适度防抖并允许 Enter 立即提交；加载中不要每个字符都产生屏幕阅读器播报。
- 批量操作完成后用非打断式状态消息播报“已审核 18 条；2 条未处理”，并把键盘焦点留在逻辑上连续的位置；仅在操作需要用户处理错误时再移焦点。
- 禁止纯装饰性的长时动画、自动滚动到结果或遮挡表格的全屏加载层；动效应可遵从系统“减少动态效果”偏好。

## 无障碍要求（WCAG 2.1 AA）

| 关注点 | 适用要求与落地建议 | 依据 |
|---|---|---|
| 语义表格优先 | 纯展示性数据使用原生 `<table>`、`<caption>`、`<th scope>`；只有需要箭头键单元格导航、内联编辑等复合交互时才采用 ARIA `grid`。`grid` 会要求自行实现焦点管理，不能只添加角色。 | [WAI-ARIA Grid Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)、[USWDS Table](https://designsystem.digital.gov/components/table/) |
| 键盘可用 | 搜索、筛选、列菜单、分页、行选择、批量栏、确认/取消和错误重试都必须可仅用键盘完成，且无键盘陷阱。原生控件优先；自定义菜单、弹窗和网格要实现对应键盘模式。 | [WCAG 2.1 SC 2.1.1](https://www.w3.org/WAI/WCAG21/Understanding/keyboard) |
| 焦点顺序与可见焦点 | Tab 顺序按视觉与任务顺序经过工具栏、表格、分页；筛选弹层/确认弹窗开启时管理焦点，关闭后回到触发控件。每个可操作控件都要有持续可见的焦点指示。 | [WAI Keyboard Interface Practice](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)、[WCAG 2.1 SC 2.4.7](https://www.w3.org/WAI/WCAG21/Understanding/focus-visible.html) |
| 多选语义 | 每行复选框有包含记录主标识的可访问名称；表头复选框说明其范围（例如“选择本页 50 条”），部分选择使用原生 `indeterminate`/`aria-checked="mixed"`。 | [WAI-ARIA Checkbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/) |
| 动态状态 | 加载、结果数、选择数、批量操作成功/失败和进度以适当的 `role="status"` / `aria-live` 等可编程方式告知，不抢夺用户焦点；不要逐行播报大量变化。 | [WCAG 2.1 SC 4.1.3](https://www.w3.org/WAI/WCAG21/Understanding/status-messages) |
| 非文本对比度与非颜色提示 | 复选框勾选、排序方向、筛选已启用、错误、禁用和焦点等重要控件/状态相对相邻颜色至少达到 3:1，并配合图标、文本或形状，不能只靠颜色。 | [WCAG 2.1 SC 1.4.11](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast) |
| 缩放与窄视口 | 在 400% 缩放/约 320 CSS px 的阅读环境下，工具栏和弹层仍可使用。数据表允许必要的二维滚动，但每个单元格内容、固定列和操作入口仍须可见、可达且不丢失功能。 | [WCAG 2.1 SC 1.4.10](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html) |
| 分页语义 | 分页放入描述性的导航区域，当前页使用 `aria-current="page"`；不要让仅图标的上一页/下一页缺少名称。 | [USWDS Pagination](https://designsystem.digital.gov/components/pagination/) |

## 平台考量

### Web 后台（主要场景）

- 桌面优先，但必须支持键盘、屏幕阅读器、浏览器缩放及窄窗口。大数据表可使用容器级横向滚动；首列/关键标识列可在确认实现可访问性后固定。
- URL 应可表示搜索、筛选、排序和分页，使审核队列可刷新、分享与返回；不得在 URL 或浏览器历史中暴露敏感查询内容。
- 远程分页、筛选和批量选择的“作用范围”必须由服务端以稳定查询快照或等价机制验证；这是防止用户界面与实际处理对象漂移的交互前提，而非前端单独可保证的能力。

### 小屏/触控（次要场景）

- 若后台需要在小屏可用，保留搜索、筛选、结果数、选择数和关键行操作；次要列可藏入行详情或列显示菜单。避免把复杂表格强制堆叠为难以比较的卡片。
- 触控目标建议至少约 44×44 CSS px，行内溢出菜单与复选框应有足够间距；所有触控路径仍必须有键盘等价路径。

## 需避免的反模式

- 将“全选”默认为所有分页或所有数据库记录，却不显示范围与数量。
- 把批量审核、发布、删除等高影响操作藏在无标签图标或二次菜单深处，且没有确认或处理结果。
- 搜索、筛选改变了结果，但仍保留旧页码、旧选择或没有说明结果数。
- 用同一个“暂无数据”页面同时表达首次空列表、筛选无匹配、加载中和加载失败。
- 让批量操作静默忽略无权限、状态不符或并发已变更的记录。
- 过度 ARIA：把普通静态表格强行做成 `grid`，却没有完整的箭头键、编辑态与焦点管理。
- 只通过灰度、颜色或 hover 暗示筛选、选择、排序、错误或可点击性。
- 将列显示视为权限控制，或允许隐藏使行失去唯一可识别的信息。

## 建议方向

建议以“结果集工具栏 + 语义表格 + 上下文批量栏 + 明确分页范围”组成基础框架：搜索和分面筛选先定义当前查询，选择和批量操作只作用于被明确标识的范围。优先交付可见搜索、关键分面、当前页选择、已选计数、审核操作、分页及完整状态反馈；跨查询全选、列偏好持久化和高级筛选应在服务端范围定义、权限、状态机与审计方式确认后再启用。实现时优先使用原生 HTML 语义和既有组件库能力，只有真正需要电子表格式交互时再引入 ARIA grid。所有异步结果及部分失败必须同时有视觉摘要和可访问状态消息。
