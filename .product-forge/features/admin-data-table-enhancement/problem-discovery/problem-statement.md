# 问题陈述画布：管理端通用数据表增强

> 状态：`designing`。本文件是 Product Forge 阶段性研究输入，不构成产品、领域、架构或 API 事实源。

## 问题

**一句话：**内容管理员在高频审核后台列表时，缺少统一的搜索、筛选、多选、批量审核与可扩展分页能力，因而无法高效地完成成批审核工作。

**受影响用户：**使用管理端内容列表执行日常审核与处置的内容管理员。

**当前情境：**现有 `DataTable` 已具备基础排序、客户端分页、列显示开关及可选行状态，但缺少可直接采用的选择列、批量操作工作流、统一筛选/搜索契约，以及与服务端 Offset 分页一致的状态模型。

**摩擦点：**管理员需要定位和审核多条记录时，无法在同一个列表工作区完成筛选、跨行选择与安全批量处置。

**不解决的后果：**内容审核工作无法有效执行；不同列表页会各自实现交互，造成操作行为、权限提示和审计覆盖不一致。

## 待完成的工作（JTBD）

**当：**我需要在大量内容记录中完成日常审核或处置时，

**我想要：**按条件快速定位记录、选择多条并执行获授权的批量操作，

**以便：**在一个一致、可控且可追溯的列表工作区完成审核。

**功能性工作：**搜索、筛选、浏览分页结果、选择记录、发起批量审核动作。

**情感性工作：**对所选范围和批量操作结果保持掌控与信心。

**社会性工作：**作为可靠的内容管理员及时、准确地处理审核队列。

## 当前方案审计

| 方案 | 使用者 | 为什么不足 | 机会 |
| --- | --- | --- | --- |
| 逐条查看与操作 | 内容管理员 | 高重复成本，不能完成批量审核 | 将多选与受控批量动作纳入统一列表工作流 |
| 各页面自行组合工具栏 | 各领域页面开发者 | 交互、权限与错误处理不一致 | 提供可复用且可配置的 DataTable 能力 |
| 当前通用 DataTable | 内容管理员 | 缺少业务可用的搜索、筛选及批量操作契约 | 扩展为面向管理端列表的基础设施 |

## 关键风险

1. “批量审核”在不同内容域中的允许动作、状态转换和权限尚未统一定义，通用组件不得越权假定业务语义。
2. 现有部分列表使用客户端数据集，部分 API 可能需要 Offset 或游标分页；不能将客户端分页误作通用大数据方案。
3. 跨页全选的范围、上限、失败反馈、确认步骤与操作审计要求尚未明确。

## 研究假设

- H1：内容管理员的主要批量任务可归纳为有限的、领域声明的动作，而非由通用表格任意提供写操作。
- H2：搜索、筛选、列可见性、排序和分页可以采用 URL 状态，与管理端既有 TanStack Router 状态所有权一致。
- H3：通用组件能支持服务端 Offset 分页，同时保留当前小数据集的客户端模式，且不改变既有领域 API 契约。
