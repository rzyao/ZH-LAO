# 内容层级管理后台：用户体验模式研究

> 研究结论是功能设计输入，不是产品、领域、数据库或接口的权威定义。现行权威的版本与审核规则见 [Content 版本与审核](../../../../docs/docs/developer/reference/domains/content/versioning-review.md)。

## 1. 已确认的设计输入

| 语言 | 层级 | 不可混用约束 |
| --- | --- | --- |
| 老挝语 | 字母 → 音节 → 词语 → 句子 | 每一层仅链接老挝语实体。 |
| 中文 | 拼音 → 发音/中文音节 → 汉字 → 词语 → 句子 | “发音”是独立的中文音节实体，不是音频资产；每一层仅链接中文实体。 |

首期仅提供后台。中文与老挝语必须使用独立物理表；本研究不建议用跨语言通用词条表替代这一边界。音频生产和版本仍属于 Audio 域：内容后台只展示关联状态或进入音频工作流，不把音节“发音”误建为音频文件。

## 2. 建议的信息架构与编写流程

### 2.1 双语言工作区，而非一个可切换字段的混合列表

后台入口采用目录工作区：`中文内容` 与 `老挝语内容`。每个内容类别必须作为侧边栏的独立路由注册，而非页面内标签：`内容管理 → 中文内容/老挝语内容 → 内容类别`。目录由统一递归节点自由组织；列表、详情、关系编辑与版本比较保留在类别页内。进入工作区后，使用同语言的列表、详情和“创建下级”动作：

```text
中文：拼音 → 中文音节 → 汉字 → 词语 → 句子
老挝语：字母 → 音节 → 词语 → 句子
```

- 在列表页同时提供层级树/面包屑（定位）与可筛选表格（运营查找），不要让树承担大规模搜索。
- 详情页显示“组成项”和“被引用于”两个独立区块，均显示版本、发布状态和依赖是否满足；用位置编号维护组成顺序。
- “从当前项创建下级”预填父项与位置；全局创建保留为专家入口，并在提交前明确选择父项。这样既能支持自顶向下教学编排，也能处理先录入词条、稍后补齐拆分关系的运营流程。
- 中文界面不把 `拼音` 与 `中文音节` 合并：前者是基础拼写/声调输入，后者是可独立审核、发布和被汉字引用的内容项。详情中可用“来源拼音”和“该音节关联的汉字”表达两者关系。
- 老挝语音节编辑器使用按位置的字母组成器，显示角色（声母、元音、韵尾、声调标记等）；不在界面中暗含或硬编码复杂拼读规则。

### 2.2 面向审核的编辑体验

- 工作版本显示为清晰的主状态：`草稿 / 待审核 / 已通过 / 已发布 / 已驳回 / 已归档`；上线状态另列为 `上线 / 下线 / 已删除`，绝不以一个彩色标签混淆两种状态。
- 已发布版本仅可查看和比较。点击“编辑”创建后继工作版本，而不是在原版本上原地修改。
- 编辑页保留“与当前发布版比较”：字段差异、组成关系差异、受影响的下游项、以及音频输入是否变化。提交审核前提供只读预览。
- 审核台按“待我审核、被驳回、即将发布、依赖阻塞”分组；审核详情提供版本差异、评论或驳回原因与可追溯操作记录。批准与发布是两个明确动作。

## 3. 依赖与发布验证

| 操作 | 后台应给出的验证与可执行下一步 |
| --- | --- |
| 保存草稿 | 允许不完整；标记缺失字段/未选父项，不阻断继续编辑。 |
| 提交审核 | 校验必填字段、组成顺序连续、父/子关系语言一致、关系目标存在且可用；错误指向字段或关系行。 |
| 批准 | 显示本版本、被引用依赖和审核意见；不自动将它公开。 |
| 发布 | 校验组成依赖已有合法已发布版本、目标工作版本仍是当前活动版本、所需音频槽位状态符合实体规则；失败时列出阻塞项与跳转链接。 |
| 下线/归档 | 显示会受影响的下游引用和 C 端可见性后果；对不可逆或高影响动作要求明确确认。 |

发布检查必须在服务端再次执行；浏览器内的即时校验只是减少返工，不能成为发布正确性的唯一依据。批量操作先生成“将发布/将阻塞”的预检清单，再要求确认，避免把部分成功伪装成完整成功。

## 4. 状态、错误与冲突处理

| 场景 | 推荐交互 |
| --- | --- |
| 首次进入/无数据 | 按当前语言与层级说明用途，提供“创建首个拼音/字母”主操作和导入入口（若后续范围批准），不使用空白表格。 |
| 加载中 | 表格和详情使用骨架屏；提交、审核、发布按钮显示处理中且防止重复提交，同时保留可读的当前状态。 |
| 无匹配结果 | 保留筛选条件，提供“清除筛选”和在当前层级创建内容，避免误导为系统无数据。 |
| 保存失败 | 保留输入内容；给出能行动的错误文本、重试和关联字段定位。网络失败不得把未保存内容误报为已保存。 |
| 依赖阻塞 | 在状态列标示“阻塞”，详情给出缺失/未发布/已下线的依赖列表与跳转，而不是只有“发布失败”。 |
| 乐观锁冲突 | 显示“其他人已更新此工作版本”、对比本地与服务器版本，并提供重新载入、复制本地草稿或逐字段合并；禁止静默覆盖。 |
| 审核拒绝 | 固定展示驳回原因、审核人和时间；“继续编辑”基于被拒绝版本创建或恢复合法工作版本。 |

对真正会中断工作流并需决定的发布/下线/冲突确认使用模态对话框；普通保存成功、后台校验完成等状态用非阻塞状态消息。W3C 指出 `alertdialog` 应在打开时把焦点置入其中、在关闭后回到原位置；对动态表单错误，错误摘要应链接到相应字段并说明修复方式。[W3C alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/)；[W3C form notifications](https://www.w3.org/WAI/tutorials/forms/notifications/)。

## 5. 可访问性与语言输入要求

- 所有状态不能只靠颜色：发布、阻塞、驳回同时给出文字、图标和可读状态名称；状态变更使用适当的 live region。
- 筛选、树、关系编辑行和审核动作必须完整键盘可达；焦点顺序与视觉顺序一致。复杂输入保持纵向分组，并把校验消息放在相应字段附近。[USWDS Form guidance](https://designsystem.digital.gov/components/form/)。
- 对格式较严格的拼音/声调输入，先给出示例和允许格式，用户交互后再显示格式错误；不要以输入掩码取代语义验证。[USWDS Input mask guidance](https://designsystem.digital.gov/components/input-mask/)。
- 支持中文、老挝文及拉丁转写的复制、粘贴、IME 输入和 Unicode 正规化提示；搜索应明确当前工作区，不跨语言自动“猜测”等价项。
- 关系编辑控件需要可读的项名、类型、版本和状态，不能只显示字符本身；这对同形字符、声调和屏幕阅读器尤为重要。

## 6. 对后续规格的可验证建议

1. 每个语言工作区和详情页只能查询、创建、关联本语言的物理内容实体；跨语言关联尝试必须被拒绝并报告明确原因。
2. 管理员可从任一已保存项查看组成关系、反向引用和每一项的当前发布/工作版本。
3. 任何已发布内容的编辑都会生成后继工作版本；审核、发布和下线均有可追溯事件。
4. 发布操作在依赖未发布、已下线或版本冲突时不成功，并返回可定位的阻塞清单；不会产生部分静默发布。
5. 错误、冲突和确认流程包含文本说明、键盘焦点管理及恢复路径。

## 7. 风险与需要权威裁决的事项

- 当前[知识规格](../../../../docs/docs/developer/reference/domains/content/knowledge.md)的冻结中文表只列 `zh_pinyin`、`zh_hanzi`、`zh_words`、`zh_sentences`，但[音频绑定](../../../../docs/docs/developer/reference/domains/content/audio-binding.md)已提及 `ZhSyllable`。本功能已确认需要独立中文音节实体；在计划或实现前，Content/Database 权威必须给出该实体、父子关系、内容类型及其冻结迁移策略，不能由界面或本研究推断补齐。
- 整组内容一致性发布、多分支协作和分级审核权限仍是版本审核领域的未决事项；首期仅按现有单实体发布指针设计，不能暗中将批量发布视为已确认能力。
