# 研究索引：中老语言内容层级

> 生成日期：2026-09-04｜功能：`chinese-lao-content-hierarchy`  
> 输入完整度：5/8｜访谈方式：部分访谈  
> 研究维度：竞品、用户体验、代码库

## 执行摘要

首期应提供相互独立的中文和老挝语后台工作区、语言专属组成编辑器，以及既有不可变 Content 版本生命周期。老挝语字母管理可作为实现参考；其他语言管理尚未完成。中文音节需求已确认，但其物理权威契约仍需一次性决策。

## 关键发现

| 维度 | 核心结论 |
| --- | --- |
| 竞品 | 正式内容必须与草稿隔离，发布前应显示层级影响。 |
| 用户体验 | 使用分离工作区、有序关系编辑、依赖预检和可恢复冲突界面。 |
| 代码库 | 复用老挝语字母流程与通用版本生命周期，但先补齐中文音节契约。 |
| 约束 | 语言结构表分离；首期仅后台；Audio 继续负责音频生产。 |

## 综合建议

将两种语言树建模为相互独立的 Content 子模型，并在后台侧边栏中分别呈现。`content.contents` 和 `content.content_revisions` 只承载共享身份与版本治理，不存语言结构字段。先通过集中决策确定中文音节、有序拼音组成、汉字关联和发布依赖，再将已验证的老挝语字母草稿、审核、发布与 Operations 审计模式扩展到所有类别。首期不包含移动端或 Audio 音频生产。

## 产品规格待处理问题

1. 中文音节、拼音元素及二者有序关系采用什么字段和规范化规则？
2. 两种语言的词语到句子关系如何表达顺序、重复和标点？
3. 哪些类别级权限键用于读取、编辑、审核和发布，并如何保持角色自定义？

## 已识别风险

- 尚无冻结的中文音节及拼音组成数据结构。
- 新层级与现有完整音节含义的 `zh_pinyin` 表存在语义冲突；用户已决定一次性切换，不做旧版运行兼容。
- Audio 文档与实现的声调槽位存在差异，推迟到中文音频集成前处理。
