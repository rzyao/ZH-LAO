# Menu tree delta specification

## MODIFIED Requirements

<!-- CR-001: drag reorder and reparent -->

### FR-003 — 菜单树层级

菜单树采用统一节点模型，不区分分组和固定层级。任一未移除节点都可处于根目录或作为其他
节点的子项，并可同时拥有 `route_key` 与子项；缺少 `route_key` 的节点为目录。<!-- CR-004 -->

### FR-006 — 排序与换父级

运营人员可以通过拖拽在同层重新排序，或把节点移动到另一个有效父项（含顶层）。服务端
必须原子保存父级变更与源/目标层连续排序。

### FR-011 — 并发与树完整性

移动必须校验被移动节点、源层和目标层的快照。服务端必须拒绝自环、后代环和已移除父项，
并以既有并发冲突语义返回陈旧提交；不设置业务深度上限。<!-- CR-004 -->

### FR-018 — 侧边栏目录初始状态

每一层含子项的目录默认收起。当前路由命中后代不得自动展开其父目录；操作员点击后才切换
展开状态。<!-- CR-004 -->

### FR-019 — 总览入口呈现

「总览看板」作为根目录直接入口，不再保留专门的总览分组。<!-- CR-004 -->

### FR-020 — 统一递归呈现

Sidebar 必须以统一字号和交互递归呈现目录与页面；带路由且含子项的节点点击菜单项目时同时
跳转并伸缩，箭头只伸缩、不跳转，并暴露 `aria-expanded`。菜单名称与箭头共用整行选中背景
和左侧高亮边。菜单管理页允许在任意层级新建子项。<!-- CR-005 -->

## ADDED Requirements

### FR-017 — 拖拽菜单编辑器

菜单管理页 MUST 提供可通过鼠标、触摸和键盘操作的拖拽树编辑器；清晰显示有效落点、当前
层级及保存/冲突反馈，且不得仅依赖颜色表达状态。
