# 产品规格：字母管理 UI 优化

> 状态：DRAFT｜版本：1.0｜日期：2026-09-05｜规模：小型

## 概览

内容管理员当前可以在 `/content/lo/letters` 搜索、筛选、选择字母并发起批量审核/发布/归档任务。页面功能已较完整，但列表、筛选和选中提示需要更清晰的主次关系。

本次仅优化 `apps/admin` 的视觉组织与交互反馈：明确页面概览、筛选工具栏、表格工作区与选中操作区的主次关系；复用现有设计系统，并完整保留 URL 查询参数、服务端分页、权限、异步批量任务和既有错误处理。

## 用户与目标

**主要用户：** 具有内容管理权限的后台操作员。

**主要目标：** 操作员能够快速定位字母记录、判断当前筛选/选择上下文，并放心地进入既有批量操作和任务跟踪流程。

## 用户故事

- **US-001**：作为内容管理员，我想一眼看到当前字母列表的数量、筛选状态与可用操作，以便快速进入正确的管理任务。
- **US-002**：作为内容管理员，我想搜索和组合筛选条件时获得清晰、稳定的反馈，以便确认我正在处理的范围。
- **US-003**：作为内容管理员，我想在选中记录后看清批量操作与任务状态，以便避免误操作并跟踪结果。
- **US-004**：作为内容管理员，我想在选择记录后清楚看到既有批量操作与任务进度，以便安全地跟踪已有操作流程。
- **US-005**：作为具有字母写入权限的内容管理员，我想在同一页面新建字母草稿、编辑可编辑草稿或从正式版本派生新草稿，以便完成日常维护而不离开当前工作流。 <!-- CR-002: 补齐字母管理 CRUD -->
- **US-006**：作为内容管理员，我想以明确的归档操作移除不再使用的字母，以便列表数据保持可维护，同时保留审计与历史记录。 <!-- CR-002: 补齐字母管理 CRUD -->

## 功能需求

| ID | 要求 | 优先级 |
| --- | --- | --- |
| FR-001 | 页面沿用既有标题区，并让筛选工具栏和字母数据表成为默认工作区。 | Must |
| FR-002 | 搜索和筛选控件在视觉上组成工具栏；活跃筛选应可辨认，且保留现有 URL 同步和清除筛选行为。 | Must |
| FR-003 | 表格工作区应以卡片式边界、稳定表头和适当留白改善扫描效率；不得改变列、排序、分页、行选择或音频试听功能。 | Must |
| FR-004 | <!-- CR-001: 默认不展示任务历史。 --> 只有选择记录时才突出显示批量操作上下文；仅在刚发起操作后展示当前任务详情。 | Must |
| FR-005 | 加载、无结果、错误和后台刷新状态必须保持清晰、可访问且不造成布局跳动。 | Must |
| FR-006 | 采用既有 `Button`、`Input`、`Badge`、`Table`、`Skeleton` 与 CSS 令牌；触控目标和键盘焦点样式不得退化。 | Must |
| FR-007 | <!-- CR-002: 补齐字母管理 CRUD。 --> 具有 `content.lo_letters.write` 权限时，页面提供“新建字母”入口，并通过既有 `POST /api/v1/admin/content/lo/letters` 创建仅含规范字段的草稿。 | Must |
| FR-008 | <!-- CR-002: 补齐字母管理 CRUD。 --> 列表记录可编辑当前草稿；没有工作草稿的已发布记录必须先通过既有 `derive-working` 派生草稿，保存时携带乐观锁版本。 | Must |
| FR-009 | <!-- CR-002: 补齐字母管理 CRUD。 --> “删除”在界面中明确标示为归档，复用既有异步批量 `archive`、原因必填和二次确认；不得提供物理删除。 | Must |

## 非功能要求

| 类别 | 要求 |
| --- | --- |
| 可访问性 | 所有操作保留可见焦点、语义标签与状态通知；颜色不是唯一状态表达。 |
| 响应式 | 窄屏下工具栏和标题操作可换行；表格维持现有横向滚动机制。 |
| 主题 | 使用现有 CSS 变量，不硬编码会破坏深色主题的新颜色。 |
| 性能 | 不新增列表请求、不改变 300ms 搜索防抖或服务端分页。 |

## 明确不在范围内

- 不修改 Content Domain、`LaoCharacter` 分类/排序/音频规则。
- 不改动任何后端 API、数据库、权限、批量任务状态机或任务结果；CRUD 仅接入已存在的 API。
- 不新增批量动作、字母字段、审核规则或新页面。
- 不重写现有通用数据表组件。

## 验收标准

1. 在默认、筛选、选择、加载、无结果和错误状态下，操作员都能在视觉上辨认当前上下文和下一步操作。
2. 搜索、筛选、排序、分页、列显隐、选择、批量操作、任务查看和音频试听的已有行为不回归。
3. 选择记录后，既有批量操作和任务进度在视觉上可辨认，且不改变确认或执行流程。
4. 管理页面在浅色和深色主题下保持令牌一致性，键盘焦点与屏幕阅读器提示可用。
5. 具备写入权限的操作员能新建草稿，并能保存当前草稿；正式版本先派生工作草稿再编辑，发生并发冲突时不覆盖较新版本。
6. 归档必须继续经过现有的原因填写、二次确认和异步任务流程，页面不得展示或调用物理删除。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 为了美化而遮蔽批量操作的高风险语义 | 仅在已有选择状态下强调操作区，不改变确认和任务流程。 |
| 页面调整造成查询状态不同步 | 保留 `LaoLetterPage` 现有的 URL 搜索状态与回调。 |
| 视觉代码与组件库漂移 | 只复用已提取的组件和 CSS 变量。 |
