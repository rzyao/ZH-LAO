# 产品规格：后台操作员密码重置

> 状态：DRAFT｜版本：1.0｜日期：2026-09-05
> Feature：`admin-operator-password-reset`｜规模：Medium
>
> **上游权威待修订：** 本文记录用户已确认的拟定基线，不替代 Identity、Operations、API 或数据库权威。实施前必须将获批规则写入对应唯一事实源。

## 1. 概览

### 问题

后台操作员的初始密码只在创建时显示一次。若密码未安全留存或需要收回访问权限，当前没有受控的管理员重置流程，管理者无法安全恢复另一名后台操作员的登录访问。

### 方案

在“操作员管理”中为有精确权限的管理员提供目标上下文内的密码重置操作。成功的单一命令生成新的临时密码、更新目标后台凭证、撤销其全部会话并写入 Operations 成功审计；临时密码仅在成功结果中显示一次，目标必须在首次登录时改密。

## 2. 使用者与边界

### 主要使用者

持有 `operations.operators.reset_password` 权限的活跃后台操作员；只有 `super_admin` 可以重置持有 `super_admin` 角色的目标。

### 范围内

- 重置**其他**活跃后台操作员的独立后台账号密码。
- 生成并一次性返回新的临时密码。
- 更新凭证、撤销目标全部会话、写成功审计的全有或全无事务。
- 管理端确认、一次性秘密展示、复制、无障碍和错误状态。

### 范围外

- 自己重置：继续使用既有“修改登录密码”。
- 匿名“忘记密码”、Mobile 用户、邀请、邮件/短信投递、MFA、SSO。
- 已禁用操作员、没有 active Identity 或没有后台凭证的目标。
- 通过 GET、审计、日志、列表、浏览器持久化状态或查询缓存找回临时密码。
- 自动重放或在响应丢失后恢复同一临时密码。

## 3. 用户故事

- **US-001**：作为有重置权限的管理员，我要在目标操作员上下文中确认重置，以便安全恢复其后台访问且立即收回旧会话。
- **US-002**：作为执行重置的管理员，我要仅在成功后复制一次新临时密码，以便通过批准渠道交付而不在系统中留下明文秘密。
- **US-003**：作为安全负责人，我要限制特权账号重置、强制首次登录改密、拒绝自动重试并完整审计，以便防止越权、秘密泄露与部分成功。

## 4. 功能需求

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-001 | 系统 MUST 新增并由后端强制执行精确权限 `operations.operators.reset_password`；前端可见性不得替代授权。 | Must |
| FR-002 | 仅 active 的 actor 可重置**其他** active Operator；actor 不得通过本流程重置自己。 | Must |
| FR-003 | 目标持有 active `super_admin` 角色时，actor 也 MUST 持有 active `super_admin` 角色；否则拒绝。 | Must |
| FR-004 | 一次成功重置 MUST 在同一事务内完成：生成合规随机临时密码、替换目标凭证哈希、撤销目标全部活跃会话、写入成功 Operations 审计；任一步失败 MUST 整体回滚。 | Must |
| FR-005 | 成功响应 MUST 仅一次返回临时密码，使用统一成功信封与禁止缓存响应头；密码不得进入审计 details、日志、错误、URL、列表、详情、查询缓存或持久化前端状态。 | Must |
| FR-006 | 目标使用临时密码首次成功登录时 MUST 被引导且强制完成密码修改，才能继续访问后台受保护资源。 | Must |
| FR-007 | 管理端 MUST 在目标操作员上下文内提供二次确认，清楚告知旧密码失效及全部会话将结束；提交期间禁止重复提交。 | Must |
| FR-008 | 成功后管理端 MUST 在独立结果 Dialog 中展示可复制临时密码，并在关闭、刷新、离开或失败时清除组件内存中的秘密。 | Must |
| FR-009 | 网络错误或响应丢失时客户端 MUST 不自动重试；管理员须刷新目标状态后主动发起新的重置，系统不得通过读取接口再次泄露任何临时密码。 | Must |
| FR-010 | 审计 MUST 记录 actor、目标 Operator、操作键、请求关联信息与成功结果，不得记录密码、哈希、令牌、session 标识或数量。 | Must |

## 5. 验收场景

### FR-004-AS01：成功重置为单一安全事务

**Given** actor 和非自身目标均为 active，actor 具备精确权限，且特权层级规则满足，
**When** actor 确认重置，
**Then** 系统在同一事务中更新凭证哈希、撤销目标全部活跃会话并写入一条无秘密的成功审计；成功响应仅一次包含新临时密码。

### FR-002-AS01：禁止自己重置

**Given** actor 打开自己的操作员操作，
**When** actor 尝试调用重置命令，
**Then** 服务端拒绝，且凭证、会话和审计均不改变。

### FR-003-AS01：保护超级管理员目标

**Given** 目标持有 active `super_admin`，而 actor 没有该角色，
**When** actor 请求重置，
**Then** 服务端拒绝，且不生成或返回临时密码。

### FR-006-AS01：临时密码首次登录强制改密

**Given** 目标已获得新的临时密码，
**When** 目标用该密码完成登录，
**Then** 系统只允许其完成密码修改；完成前不得继续访问受保护后台资源。

### FR-009-AS01：响应丢失不重放秘密

**Given** 服务端已成功提交重置但客户端未收到响应，
**When** 客户端遇到网络错误，
**Then** 客户端不自动重试，也没有任何读取接口返回该临时密码。

## 6. 非功能与安全要求

- 统一响应信封、顶层 `request_id` 与已登记业务状态码遵循 ADR-023。
- 目标操作、凭证/会话变更与审计必须保持 Identity/Operations 的唯一归属边界：Operations 不直写 `identity.*`。
- 确认及结果 Dialog 支持键盘、焦点恢复、状态消息和可见焦点；操作不可仅以颜色表达。
- 不新增公开账号枚举面；受认证后台命令的错误仅向已授权管理者提供安全、稳定的说明。

## 7. 成功标准

1. 成功重置的凭证、会话撤销和审计事务一致性集成测试全部通过。
2. 临时密码在成功响应外的后端日志、审计响应、管理端缓存和持久化存储中检索结果为零。
3. 无权限、自己重置、非特权 actor 重置 `super_admin`、停用目标和失败回滚均有自动化覆盖。

## 8. 风险与待权威确认

| 风险/问题 | 处理方向 |
| --- | --- |
| 首次登录强制改密需要持久化状态 | 预期需要前向迁移或既有等价持久化机制；计划阶段必须以数据库权威裁定。 |
| 新权限/审计动作/错误码未登记 | 先修订 Operations 权威、业务状态码词汇表和 API 契约，再编码。 |
| 重置响应丢失 | 不自动重试且不再暴露秘密；管理员明确发起新的重置。 |
| 审计写入失败 | 同一事务回滚，避免“已重置但无审计”的成功状态。 |
