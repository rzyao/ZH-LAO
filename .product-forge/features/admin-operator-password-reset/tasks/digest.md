# 任务拆分摘要

## 关键决定

- 共 12 个任务、4 个顺序阶段；数据模型和 Identity 是所有后续工作的前置条件。
- T002、T004、T006、T008 均为测试优先任务，分别覆盖强制改密、原子/越权、HTTP 秘密边界和管理端秘密生命周期。
- 没有 XL 任务；两个 L 任务分别是跨域事务编排和管理端认证/对话框接入，应保持小提交并由集成测试保护。

## 产物

- `tasks.md` — 按依赖顺序的实施清单。
- `traceability.yml` — 从需求到任务的初始映射。

## 开放风险

- 迁移编号需在实施前确认；T001 不能假定 `1360` 尚未被占用。
- 受限认证 allowlist 和跨域 transaction 是安全关键点；实现开始时必须先完成相应 Red 测试。

## 交接说明

从 T001、T002 开始，确认失败测试后依次实施 T003 至 T012。建议按 Identity、Operations、Admin、文档/验证四组提交，避免把秘密处理与无关 UI 改动混在同一提交。
