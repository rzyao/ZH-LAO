# 研究索引：后台操作员密码重置

> 生成时间：2026-09-04 | Feature：`admin-operator-password-reset`
> 输入完整度：6/8 | 访谈模式：CONFIRM
> 研究维度：竞品、管理端 UX/UI、代码库集成

## 执行摘要

本功能是受认证、精确授权的后台管理命令，不是面向公众的“忘记密码”入口。推荐的基线是：授权管理员在目标操作员上下文内确认后，系统在同一 PostgreSQL 本地事务中生成临时密码、更新其哈希、撤销目标身份的全部会话并写入成功审计；明文仅在带 `no-store` 的成功响应中返回一次。

现有基础设施已覆盖密码哈希、会话撤销、Operations 授权/审计和创建后台账号时的跨模块本地事务。现有权威尚未定义新权限、目标资格、自己重置限制、临时密码首次使用规则及重试语义；这些必须在产品规格和权威契约修订中明确，不能从现有代码推断。

## 关键发现

| 维度 | 核心结论 |
| --- | --- |
| 竞品 | 最小权限、一次性显示临时密码、撤销既有会话和不记录秘密是成熟后台管理模式。 |
| UX/UI | 操作应位于目标操作员上下文内，经二次确认后展示一次性密码；必须支持键盘焦点与状态消息。 |
| 代码库 | 可复用 Identity 密码/会话能力、Operations 精确权限/审计和既有本地事务编排；预期无需数据库迁移。 |
| 约束 | Identity 仍拥有凭证和会话；Operations 不得直写 Identity SQL；新权限和审计动作需先获得权威登记。 |

## 推荐方案

将此命令限制为拥有新增精确权限 `operations.operators.reset_password` 的活跃后台操作员。后端以目标 Operator UUID 解析其 Identity 主体，由 Identity 专有端口在同一事务内完成密码更新与会话撤销；Operations 在该事务内写成功审计，且不记录密码、哈希、令牌或会话标识。管理端复用操作员行操作和一次性秘密展示模式，使用组件本地状态保存临时密码。

## 产品规格前必须裁定的问题

1. actor 能否重置自己、同级或更高权限操作员的密码？目标必须满足哪些 active 状态？
2. 是否强制目标首次登录后修改临时密码？若否，临时密码的唯一失效条件是什么？
3. 响应丢失后，重试如何避免生成不可恢复的第二个临时密码？
4. 凭证更新、会话撤销和审计失败时是否全部回滚？

## 风险

- 明文临时密码泄露：仅成功响应一次返回，设置 `Cache-Control: no-store`，不进入日志、审计、React Query 或持久化前端状态。
- 权限越权：新增精确权限、后端强制校验，并在产品规格中明确管理者层级规则。
- 部分成功：以既有同库本地事务模式保证凭证、会话和审计一致性。
- 重放/网络超时：必须先定义幂等或安全恢复语义，禁止通过读取接口再次泄露密码。
