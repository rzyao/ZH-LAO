# 管理端操作员密码重置：UX/UI 研究

## 研究范围与既有边界

本研究仅为产品规格提供管理端交互证据，不创建或改变产品/API/领域权威。已确认的范围是：拥有 `operations.operators.reset_password` 精确权限的已认证后台管理员，可为指定后台操作员重置密码；成功后撤销目标操作员全部会话、仅本次显示新的临时密码、写入成功操作审计。

现有 ADR-025 的创建账号体验已确定“明文初始密码只在成功响应出现一次，不能进入审计、日志或后续读取”；重置体验应沿用这一秘密处理边界。Identity 仍拥有认证凭据与会话，Operations 拥有授权与成功操作审计。

## 推荐任务流（供规格阶段确认）

1. 在操作员详情页展示“重置密码”操作；无精确权限时不显示。后端仍必须独立执行权限判定。
2. 触发后打开确认对话框，明确显示目标的 `display_name` 和稳定操作员标识的短格式；不得要求输入或展示认证主体 UUID，也不得使用可编辑账号搜索作为本流程入口。
3. 确认文案应说明不可逆的即时影响：将生成新临时密码，目标操作员的全部会话立即失效；旧密码不再可用。主操作采用明确动词“重置密码”，并把“取消”作为初始焦点，降低误确认风险。
4. 提交期间禁用重复提交、保留对话框与上下文，并用非秘密状态提示告知“正在重置”。网络失败或业务拒绝时保留目标和重试入口，不清空页面状态。
5. 成功后替换为结果对话框：展示新临时密码、独立“复制密码”按钮，以及“此密码仅显示一次；关闭、刷新或离开此页后不可恢复”的醒目提醒。禁止把密码写入 URL、页面标题、toast、浏览器持久化状态、分析事件、客户端日志或审计详情。
6. 复制成功只显示“已复制”这类非秘密反馈；用户确认关闭后清除内存中的密码，再刷新目标详情数据。无需在界面中展示“撤销会话”的具体 session 数量，除非该数据被未来契约显式提供。

## 误操作与信息泄露防护

| 风险 | UI 行为 | 服务端/契约含义 |
| --- | --- | --- |
| 重置错账号 | 详情页上下文操作 + 二次确认中重复显示目标；不在确认框中提供可编辑搜索或切换目标。 | 请求以 URL 中的目标 Operator UUID 为准；服务端再次解析、授权与审计。 |
| 重复提交 | 发送后锁定确认按钮；只在确定失败后恢复。 | 应明确幂等/并发语义，避免一次点击产生多份有效临时密码。 |
| 目标不存在、已停用或无权 | 在已授权后台的详情上下文中给出稳定、可操作的错误；不凭前端可见性代替权限检查。 | 这是受认证、受授权的管理命令，不是公开“忘记密码”入口；公共匿名请求才需统一响应与耗时以避免枚举。 |
| 明文密码扩散 | 仅结果对话框内渲染；提供复制而非自动复制；关闭即删除前端内存值。 | 明文不得进入审计/日志/后续读取；服务端不应在错误、追踪或遥测字段回显。 |
| 会话失效带来的意外 | 确认前明确提示“所有现有会话将失效”，成功后声明已完成。 | 会话撤销与新凭据生效应作为同一成功语义处理；部分成功必须有稳定的恢复/重试规则。 |

OWASP 指出密码重置常见于账号枚举；对公开找回入口应使用一致的响应和耗时，并限制自动化提交。[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 本功能不应新增此类匿名入口。该来源同时建议密码变更后自动或由用户选择撤销既有会话；已确认范围采用自动撤销。

## 可访问性要求

- 确认与成功结果均使用真正的模态对话框：背景不可操作，焦点被限制在对话框中，`Escape`/可见的“取消或关闭”控件能够退出。对话框须有可见标题并正确关联标签。W3C 的 [Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 对这些键盘、焦点和语义行为有明确要求。
- 对不可逆确认，初始焦点放在“取消”或其他最少破坏性的操作，而不是“重置密码”；对成功结果，初始焦点放在说明/密码区域，使屏幕阅读器先获知一次性展示限制，再导航到复制按钮。关闭后焦点回到触发按钮，或目标详情中的逻辑后续位置。
- 复制成功、提交中、非阻塞错误使用可被辅助技术感知的状态消息，且不抢占焦点；WCAG 2.2 SC 4.1.3 要求这类不改变上下文的成功、等待或错误信息可被程序化识别。[W3C：Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)
- 所有键盘可达控件需有清晰可见的焦点指示；不要只依赖颜色表达警告、禁用或复制成功状态。[W3C：Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

## 错误呈现与待规格化项目

错误消息不得包含密码、token、认证主体 ID 或内部异常。建议按已冻结统一信封的稳定业务码映射成短而可操作的说明；未知错误只提示“未能完成密码重置，请刷新后确认目标状态再重试”，并展示 `request_id` 供支持排查。

在产品规格/API 契约阶段仍需明确：重置端点及响应形状、并发/重试幂等策略、目标为 disabled 或 Identity inactive 时的业务码、会话撤销与凭据更新的原子性边界、是否强制首次登录后修改临时密码，以及密码生成是否与 Identity 的既有策略完全一致。
